# 推免智策——项目代码运行指引

## 1. 项目说明

本目录保存“推免智策——大学生保研资格评估与升学规划智能体”工作流中使用的 3 个 Python 代码节点脚本。完整应用运行于讯飞星辰 Agent 平台，除代码节点外，还依赖平台的大模型节点、联网检索工具、分支器及统一输出节点。

## 2. 代码文件

| 文件 | 作用 | 入口参数 | 主要输出 |
| --- | --- | --- | --- |
| `01_生成精准检索词.py` | 提取学校/专业并拼接推免检索词 | `student_data` | `school_name`、`major_name`、`output` |
| `02_学校核验结果标准化.py` | 解析学校真实性和本科推免资格 | `verification_text` | `verification`、`school_verified`、`school_name` |
| `03_基础资料标准化.py` | 清洗年级、学校、专业、排名、总人数并校验异常 | `student_data` | `rank_ratio`、`data_valid`、`error` 等 |

## 3. 依赖环境与依赖库

### 3.1 Python 运行环境

- **Python：3.12**
- 三份脚本均按照讯飞星辰 Agent 平台“代码”节点的 Python 执行方式编写。
- 文件编码：UTF-8。

### 3.2 Python 依赖库

三份脚本**没有任何第三方 pip 依赖**，仅使用 Python 标准库：

| 依赖库 | 类型 | 用途 | 是否需要 pip 安装 |
| --- | --- | --- | --- |
| `re` | Python 标准库 | 正则抽取学校、专业、排名、总人数；识别学校核验文本；清洗字段 | **否** |

因此无需执行 `pip install`。只要 Python 3 环境能够正常导入 `re`，三份脚本即可运行。

### 3.3 平台级依赖（完整智能体复现必需）

仅运行三个 `.py` 文件并不能复现完整智能体。完整工作流还依赖：

1. **讯飞星辰 Agent 平台工作流环境**：用于节点编排、变量传递、分支判断和统一结束输出；
2. **大模型节点**：用于学生资料理解、联网结果分析和最终评估报告生成；
3. **联网搜索工具节点**：用于检索学校推免资格、学校/学院推免政策、培养方案及历史推免信息；
4. **分支器节点**：依据 `data_valid`、`school_verified` 等布尔变量进入成功或失败路径；
5. **文本处理/输出节点**：保存不同业务分支的文本并汇合到唯一结束节点。

> **特别说明：依赖关系分为“Python脚本依赖”和“平台工作流依赖”。Python脚本只依赖标准库 `re`；完整作品依赖讯飞星辰 Agent 平台提供的大模型、联网搜索、分支与工作流运行能力。**

## 4. 在平台中的接入方式

1. 在讯飞星辰 Agent 平台创建或打开工作流；
2. 新建“代码”节点；
3. 将对应 `.py` 文件内容复制到代码编辑器；
4. 按脚本 `main(...)` 参数名配置输入变量；
5. 按返回字典中的字段配置输出变量及类型；
6. 将输出连接至后续联网检索、大模型或分支器节点。

## 5. 三个脚本的关键逻辑

### 5.1 生成精准检索词

从 `student_data` 中提取学校和专业，并生成多组检索表达，覆盖学校推免办法、学院细则、专业培养方案、拟推荐名单与历史名额等信息。

### 5.2 学校核验结果标准化

学校核验只判断两个核心事实：学校是否真实存在、学校是否具有本科推免资格。

**学院归属未知、专业推免细则未知、专业推免率未知、竞赛加分细则未知等情况属于“后续信息不足”，不得把已经确认具有推免资格的学校判为失败。**

### 5.3 基础资料标准化

抽取并校验年级、学校、专业、排名和总人数，兼容 `64/400` 形式；当排名大于总人数、排名/总人数非正数或关键字段缺失时，返回明确错误状态。

## 6. 数据口径说明

- 本科推荐名额、拟推荐名单 + 对应本科生规模：可用于分析本科推免覆盖情况；
- “专业排名前 X% 可申请”：只能作为申请/资格门槛，**不能直接当作推免率**；
- 研究生招生中的“接收推免生人数”：属于研究生接收口径，**不能直接等同于本校本科生推免率**。

## 7. 复现流程

1. 输入学生文字和可选附件；
2. 大模型读取学生资料；
3. 使用 `03_基础资料标准化.py` 校验关键字段；
4. 使用 `01_生成精准检索词.py` 生成检索关键词；
5. 联网搜索学校推免资格、政策、培养方案和历史信息；
6. 大模型整理联网核验文本；
7. 使用 `02_学校核验结果标准化.py` 输出 `school_verified`；
8. 分支器决定进入最终评估或核验失败提示；
9. 最终大模型按大一/大二/大三生成差异化报告；
10. 各分支文本汇合到唯一结束节点。

## 8. 测试

测试数据见 `../05-其他/推免智策-10组测试数据集.txt`。测试覆盖正常流程、学校简称、基础字段缺失、排名异常、学校资格与学院细则分离、大一/大二/大三分流及大三“冲刺—匹配—稳妥”院校输出。

## 9. 注意事项

- 正式评估应优先使用学生实际推免年份的学校及学院官方文件；
- 非官方公开数据只能作为辅助，不应覆盖明确的官方政策；
- 本项目输出为升学规划辅助信息，不替代高校官方推免资格审核、学院公示或目标院校录取结果。
