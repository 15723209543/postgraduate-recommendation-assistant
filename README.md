## 3. 已实现功能

### 3.1 基础功能

基于自然语言输入提取学生年级、学校、专业、排名和人数；兼容 `64/400` 形式的排名输入；校验必填字段、排名正整数以及排名不超过总人数等规则；生成面向校级和专业级政策的检索词；从检索到的核验文本中结构化提取学校名称和学校资格状态。

### 3.2 核心规则或业务功能

核心流程为：用户输入资料 → Python 代码节点校验 → 生成关键词并联网检索 → 大模型归纳学校政策与资格核验材料 → 学校核验节点输出 `school_verified` 等字段 → 分支器给出补充提示或形成阶段性规划报告。大一、大二主要生成机会分析、短板诊断与分阶段提升建议；大三进一步提供冲刺、匹配、相对稳妥院校建议及申请时间线（以信息充足且核验通过为前提）。

### 3.3 图形界面与交互

用户通过[讯飞星辰 Agent 对话页面](https://agent.xfyun.cn/agentbuilder/chat?sharekey=f8e17e0c108bbadb020d2e82246c4d7a&botId=5774727)输入文字或按平台支持方式提供附件；系统根据资料完整性与学校资格核验结果反馈补充提示、核验未通过说明或推免机会评估报告。平台内的 Python 代码节点与模型、搜索、分支器及统一输出节点协同执行。

### 3.4 自动控制、机器人或外部引擎

外部大模型节点负责理解资料、归纳政策及生成报告；联网检索节点负责检索高校和学院官方来源；三个 Python 节点分别返回检索词与学校专业、学校核验布尔状态、基础资料字段与校验结果。代码和分支器先控制合法性及资格边界，再由大模型整理解释性文字，避免把模型回答直接当作硬性资格证据。

## 8. 模块与类关系

### 8.1 讯飞星辰 Agent 工作流编排

讯飞星辰工作流把自然语言资料输入送入解析与 Python 节点，检索政策和历史信息，处理学校资格核验，按照 `data_valid`、`school_verified` 控制后续分支，并将不同路径的输出汇合到同一结束节点。详细节点结构与连线以 `02-应用方案/推免智策_应用方案.pdf` 为依据。

### 8.2 基础资料标准化代码节点

`04-项目代码/03_基础资料标准化.py` 的 `main(student_data)` 提取 `school_name`、`major_name`、`grade`、`rank`、`total`，计算 `rank_ratio`，用 `data_valid` 和 `error` 表示是否可继续；缺项、排名非正数或排名超过总人数时返回明确错误。

### 8.3 检索词生成与学校核验节点

`01_生成精准检索词.py` 从 `student_data` 中提取学校与专业，构造关于推免办法、学院细则、专业培养方案和历史名单的搜索词；`02_学校核验结果标准化.py` 根据 `verification_text` 判断学校真实性、本科推免资格及明确失败文本，返回 `school_verified` 和学校名称。

## 9. 主要算法与实现思路

### 9.1 程序主流程

在线对话 → 解析年级/学校/专业/排名 → 代码节点检查输入 → 生成政策检索词 → 联网检索与大模型核验 → 资格布尔判断 → 按年级分流生成报告或提示补充 → 统一输出。

### 9.2 学生资料解析与排名校验

`03_基础资料标准化.py` 用正则匹配字段，兼容 `64/400` 排名记法；将排名和总人数转为整数，检查缺失、非正数以及 `rank > total`，合法时计算 `round(rank / total * 100, 2)`，输出结构化字段与错误原因。

### 9.3 检索词生成与学校推免资格核验

`01_生成精准检索词.py` 按学校和专业拼接多类政策检索表达；`02_学校核验结果标准化.py` 用规则匹配正向核验陈述与明确失败陈述，学校真实性和本科推免资格同时满足且没有失败标记时，才把 `school_verified` 设为真。对于学院细则缺失，代码不自动将学校推免资格判定为失败。

### 9.4 合法性与边界检查

需要核对年级、学校、专业和排名/人数完整性，以及排名、人数均大于零、排名不大于总人数。对无法核验学校、缺失的官方政策和不明确的高校简称，应提示用户补充，不应生成无依据的确定性推免资格结论。文本模式识别属于规则推断，相关核验仍须以高校官方资料为准。
